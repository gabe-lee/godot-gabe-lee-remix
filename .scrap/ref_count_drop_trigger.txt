In the Godot C++ source code (whether you are writing a custom engine module or a GDExtension), there are two primary ways to execute actions when a subclass of RefCounted is about to be deleted.
Approach 1: Standard C++ Destructor (~MySubClass)

Because RefCounted objects ultimately inherit from Godot's base Object class, they are allocated on the heap (using Godot's memnew) and automatically freed (using memdelete) when their reference count drops to zero.

Because they are standard C++ classes, defining a standard C++ destructor is completely valid and will run automatically.
Code Example:
code C++

// my_ref_counted.h
#include "core/object/ref_counted.h" // If writing an engine module
// Or #include <godot_cpp/classes/ref_counted.hpp> if using GDExtension

class MyRefCounted : public RefCounted {
    GDCLASS(MyRefCounted, RefCounted);

public:
    MyRefCounted();
    virtual ~MyRefCounted(); // Standard C++ destructor
};

// my_ref_counted.cpp
MyRefCounted::~MyRefCounted() {
    // Standard C++ cleanup goes here
    // E.g., freeing raw pointers, closing native file handles, stopping threads.
}

Caveats of using the Destructor:

    VTable Decay: As standard in C++, once you are inside the destructor, the object's virtual table (vtable) begins to wind down. You cannot safely call overridden virtual functions of this class or its subclasses.

    Unsafe for Godot API Interactions: By the time the C++ destructor runs, the object is in a semi-destroyed state[1]. Interacting with other Godot-specific systems, calling script methods, or triggering engine signals here can result in undefined behavior or crashes.

Approach 2: Overriding _notification with NOTIFICATION_PREDELETE

Godot's object model features a built-in notification system[1]. Right before an Object is deleted from memory, the engine dispatches NOTIFICATION_PREDELETE to it[1]. This is the recommended approach for Godot-specific cleanup logic.
Code Example:
code C++

// my_ref_counted.h
class MyRefCounted : public RefCounted {
    GDCLASS(MyRefCounted, RefCounted);

protected:
    void _notification(int p_what);
};

// my_ref_counted.cpp
void MyRefCounted::_notification(int p_what) {
    if (p_what == NOTIFICATION_PREDELETE) {
        // Execute cleanup action here
        // E.g., disconnecting connected signals, removing itself from custom registries.
    }
}

Note: In Godot's C++ source, the GDCLASS machinery automatically handles notification propagation down the inheritance chain (subclasses receive the notification first, then base classes)[2]. Because of this, you should not call the base class's _notification method (e.g., RefCounted::_notification(p_what)) manually inside your override, otherwise it will be triggered twice[2].
Caveats of using NOTIFICATION_PREDELETE:

    The "Nullified" RefCounted Reference Issue: By the time NOTIFICATION_PREDELETE is called, the internal reference count of the object has already reached 0[3]. Because of this, Godot's binding wrappers (such as GDScript, C#, and Variant) already consider the object as null/invalid[4][5].

    Do not pass this to scripts: You can safely clean up native C++ resources during this notification[1]. However, if you attempt to call a GDScript method, emit a signal that scripts are listening to, or pass this wrapped in a Variant to other systems, Godot may crash or throw errors because it detects a reference to a dying RefCounted instance[4][5].

Summary Recommendation

    If you only need to free pure C++ memory/resources (such as standard raw pointers or std::vector allocations), use the C++ Destructor.

    If you need to clean up engine-side integrations (such as shutting down background threads, clearing internal RID objects, or cleaning up references to other engine-level pointers), use NOTIFICATION_PREDELETE[6].

To achieve this, you can implement an RAII (Resource Acquisition Is Initialization) Guard pattern. You create a subclass of RefCounted (let's call it IndexGuard) that is initialized with both the uint64_t index and a reference to the manager or backing array.

When the last reference to this IndexGuard goes out of scope, its C++ destructor (~IndexGuard()) executes, calling back to the manager to mark that index as "free."

Depending on how your backing array is managed, you have two primary ways to design this:
Option A: The Backing Array is a Pure C++ Manager (Guaranteed to Outlive the Guard)

If your backing array is managed by a long-lived C++ class (like a global system, thread pool, or singleton) that is guaranteed not to be deleted before the RefCounted guards are destroyed, you can use a raw pointer to the manager.
1. The Manager Class Definition
code C++

// my_array_manager.h
#pragma once
#include <vector>
#include <mutex>

struct SlotData {
    bool is_free = true;
    // ... actual data ...
};

class MyArrayManager {
private:
    std::vector<SlotData> backing_array;
    std::mutex array_mutex; // For thread-safety if needed

public:
    void free_slot(uint64_t p_index) {
        std::lock_guard<std::mutex> lock(array_mutex);
        if (p_index < backing_array.size()) {
            backing_array[p_index].is_free = true;
            // Perform any other cleanup on the data slot here
        }
    }
    
    // Example method to reserve a slot and return the Guard
    // (See the IndexGuard implementation below)
    Ref<class IndexGuard> acquire_slot(); 
};

2. The RefCounted Guard Class
code C++

// index_guard.h
#pragma once
#include "core/object/ref_counted.h" // In Core (or <godot_cpp/classes/ref_counted.hpp> in GDExtension)

class MyArrayManager;

class IndexGuard : public RefCounted {
    GDCLASS(IndexGuard, RefCounted);

private:
    uint64_t index = 0;
    MyArrayManager* manager = nullptr;

protected:
    static void _bind_methods() {
        ClassDB::bind_method(D_METHOD("get_index"), &IndexGuard::get_index);
    }

public:
    IndexGuard() {}
    
    // Destructor executes automatically when RefCounted goes out of scope (Ref count hits 0)
    virtual ~IndexGuard() override {
        if (manager != nullptr) {
            manager->free_slot(index);
        }
    }

    void initialize(uint64_t p_index, MyArrayManager* p_manager) {
        index = p_index;
        manager = p_manager;
    }

    uint64_t get_index() const { return index; }
};

Option B: The Backing Array is a Godot Object (Safe Lifetime Management)

If the manager holding the backing array is itself a Godot Object (such as a Node, Resource, or standard Object subclass) that might be destroyed while some IndexGuard instances are still alive in memory, holding a raw pointer to it is dangerous and can cause a crash.

To prevent this, you can store the manager’s ObjectID. Before executing the free action, the destructor checks if the manager still exists.
1. The RefCounted Guard with Safe Lookup
code C++

// index_guard.h
#pragma once
#include "core/object/ref_counted.h"
#include "core/object/object_id.h"

class IndexGuard : public RefCounted {
    GDCLASS(IndexGuard, RefCounted);

private:
    uint64_t index = 0;
    ObjectID manager_id; // Safe reference that doesn't keep the manager alive

protected:
    static void _bind_methods();

public:
    IndexGuard() {}
    
    virtual ~IndexGuard() override {
        if (manager_id.is_valid()) {
            // Resolve the ID to see if the manager object still exists in memory
            Object* obj = ObjectDB::get_instance(manager_id);
            if (obj) {
                // Cast to your specific Godot manager class
                MyArrayManager* manager = Object::cast_to<MyArrayManager>(obj);
                if (manager) {
                    manager->free_slot(index);
                }
            }
        }
    }

    void initialize(uint64_t p_index, MyArrayManager* p_manager) {
        index = p_index;
        if (p_manager) {
            manager_id = p_manager->get_instance_id();
        }
    }

    uint64_t get_index() const { return index; }
};

(Note: If you are writing this in GDExtension, you can obtain the object from the ID using godot::Object::cast_to<MyArrayManager>(godot::utility_functions::instance_from_id(manager_id)))
How to use it in practice:

When your manager dispenses a new slot, it instantiates the guard, initializes it, and returns it wrapped in a Ref<T>:
code C++

Ref<IndexGuard> MyArrayManager::acquire_slot() {
    uint64_t free_index = find_next_free_slot(); // Custom logic to find a slot
    backing_array[free_index].is_free = false;

    // Create the Guard
    Ref<IndexGuard> guard = memnew(IndexGuard);
    guard->initialize(free_index, this);

    return guard;
}

Whenever this returned Ref<IndexGuard> is reassigned, cleared, or goes out of scope (either in C++ or in GDScript), Godot automatically deletes the IndexGuard instance, firing the destructor and marking the slot as free.

To safely force-delete a slot from the backing array while a reference to its IndexGuard still exists, you must solve two major safety issues:

    The Double-Free Bug: When the remaining IndexGuard reference eventually goes out of scope, its destructor will run and attempt to free the slot a second time. If another object has claimed that slot in the meantime, it will mistakenly be freed.

    The "Dangling Guard" Bug: Any system holding onto the old IndexGuard needs to know that the guard is no longer valid.

To resolve this safely, you can implement bi-directional tracking using Godot's ObjectID system. This allows the manager and the guard to safely talk to one another without creating circular reference cycles that would prevent garbage collection.
Step 1: Update the Guard Class

Add an invalidate() method to the guard. When the manager force-deletes a slot, it will find the guard and call this method. Once invalidated, the guard will ignore its destructor logic.
code C++

// index_guard.h
#pragma once
#include "core/object/ref_counted.h"
#include "core/object/object_id.h"

class IndexGuard : public RefCounted {
    GDCLASS(IndexGuard, RefCounted);

private:
    uint64_t index = 0;
    ObjectID manager_id;
    bool active = true; // Tracks if this guard is still connected to its slot

protected:
    static void _bind_methods() {
        ClassDB::bind_method(D_METHOD("is_active"), &IndexGuard::is_active);
        ClassDB::bind_method(D_METHOD("get_index"), &IndexGuard::get_index);
    }

public:
    IndexGuard() {}

    virtual ~IndexGuard() override {
        // Only perform cleanup if this guard wasn't force-invalidated
        if (active && manager_id.is_valid()) {
            Object* obj = ObjectDB::get_instance(manager_id);
            if (obj) {
                MyArrayManager* manager = Object::cast_to<MyArrayManager>(obj);
                if (manager) {
                    manager->free_slot(index);
                }
            }
        }
    }

    void initialize(uint64_t p_index, MyArrayManager* p_manager) {
        index = p_index;
        active = true;
        if (p_manager) {
            manager_id = p_manager->get_instance_id();
        }
    }

    // Called by the manager during a force-delete
    void invalidate() {
        active = false;
        manager_id = ObjectID(); // Clear reference to manager
    }

    bool is_active() const { return active; }
    uint64_t get_index() const { return index; }
};

Step 2: Update the Manager Class

The manager keeps a lookup map pairing active indices with their respective Guard ObjectIDs. When a force-delete occurs, the manager looks up the guard, detaches it safely, and frees the slot.
code C++

// my_array_manager.h
#pragma once
#include <vector>
#include <unordered_map>
#include "core/object/object.h"
#include "core/object/object_id.h"
#include "index_guard.h"

struct SlotData {
    bool is_free = true;
    // ... data ...
};

class MyArrayManager : public Object {
    GDCLASS(MyArrayManager, Object);

private:
    std::vector<SlotData> backing_array;
    
    // Tracks which Guard ObjectID belongs to which index.
    // Storing ObjectIDs instead of Ref<IndexGuard> prevents reference loops.
    std::unordered_map<uint64_t, ObjectID> slot_to_guard_map; 

public:
    // 1. Standard Allocation
    Ref<IndexGuard> acquire_slot() {
        uint64_t free_index = find_next_free_slot();
        backing_array[free_index].is_free = false;

        Ref<IndexGuard> guard = memnew(IndexGuard);
        guard->initialize(free_index, this);

        // Store the association
        slot_to_guard_map[free_index] = guard->get_instance_id();

        return guard;
    }

    // 2. Standard Clean-up (called automatically by the Guard's destructor)
    void free_slot(uint64_t p_index) {
        if (p_index < backing_array.size()) {
            backing_array[p_index].is_free = true;
            slot_to_guard_map.erase(p_index);
        }
    }

    // 3. Force Delete (called on-demand, even if a Guard reference exists)
    void force_delete(uint64_t p_index) {
        // Find if there is an active guard associated with this slot
        auto it = slot_to_guard_map.find(p_index);
        if (it != slot_to_guard_map.end()) {
            ObjectID guard_id = it->second;

            // Safely resolve the guard pointer
            Object* obj = ObjectDB::get_instance(guard_id);
            if (obj) {
                IndexGuard* guard = Object::cast_to<IndexGuard>(obj);
                if (guard) {
                    // Tell the guard it is no longer valid.
                    // This prevents its destructor from calling free_slot() again later.
                    guard->invalidate();
                }
            }
            // Remove the tracking entry
            slot_to_guard_map.erase(it);
        }

        // Physically free the slot in the backing array
        if (p_index < backing_array.size()) {
            backing_array[p_index].is_free = true;
            // (Optional: Perform immediate memory zeroing or data reset here)
        }
    }
};

Why This Design is Safe:

    No Circular References: The manager registers guards using ObjectID (which is a primitive integer wrapper). It does not hold a Ref<IndexGuard>, meaning normal out-of-scope garbage collection functions normally.

    Double-Free Immunity: Once invalidate() is called on a guard, active is set to false. When the guard's refcount drops to zero in Godot, its destructor checks active and silently terminates without trying to touch the backing array.

    Use-After-Free Immunity: Code holding a Ref<IndexGuard> can poll guard->is_active() to verify if the slot was force-freed before attempting to read or write data.
